# Oxine Apps — design

Third-party features for Oxine: compiled Swift binaries, hosted on GitHub,
installed by `creator/repo`, running **out-of-process** and rendering their UI
through Oxine's own chrome. This doc is the contract we build against.

User-facing name: **Apps** ("App Store" tab / `oxine://install/...`).
Internal name: `apps` (the module, the protocol, the folder).

## Decisions (settled)

- **No in-process code, ever.** Oxine holds TOTP secrets; loading third-party
  native code into the process would (a) let any user-level malware reach the
  Keychain by dropping a dylib in a user-writable folder, (b) chain us to an
  ABI-stable-forever kit surface, (c) make their crashes ours. The process
  boundary is the security model.
- **No JS tier.** One runner: a compiled binary (any language that can speak
  NDJSON on stdio; Swift is the blessed path via the SDK).
- **UI is declared, Oxine renders it.** Apps describe views as a tree of our
  PanelKit-styled components. Guarantees visual coherence; no ABI coupling.
- **GitHub is the registry.** `creator/repo` is the address; releases are the
  artifact store; a curated index repo powers the featured shelf only.
- **The store lives in Settings.** One clean row ("Apps") among the other
  settings sections; no store tab in the panel bar. The bar stays the user's.
- **Apps offer surfaces; the user owns placement.** The tab bar editor, footer
  slot assignment, and notch tab order stay user-controlled — an app can never
  force itself anywhere, it can only make surfaces available.
- **Footer items are one-click actions with a right-click menu.** Primary
  click fires the action/toggle; right-click shows the app's context menu.
- **x86_64 artifacts: allowed, never required.** `arm64` is the baseline.
- **Deep system work happens in the app's own process** with its own TCC
  grants (event taps, HID, MultitouchSupport, IOKit reads). Root stays
  first-party (SousHelper / TemperHelper are pinned to our signing identity).

## Architecture

```
┌─ Oxine ────────────────────────────────────┐     ┌─ app process (per app) ──┐
│ AppsManager: install/update/uninstall,     │     │ creator's binary          │
│   spawn + supervise, crash backoff         │────▶│ speaks NDJSON on stdio    │
│ AppsRenderer: view tree → PanelKit views   │◀────│ does anything a normal    │
│ Surfaces: panel tab, settings pane, footer │stdio│ process can do; own TCC   │
│   toggle, notch tab, bar metric, peek      │ JSON│ identity for permissions  │
│ Capability broker: streams + calls, gated  │     │                           │
└────────────────────────────────────────────┘     └───────────────────────────┘
```

- Install root: `~/Library/Application Support/Oxine/Apps/<id>/`
  (`manifest.json`, `bin/`, `data/` — data survives updates).
- One child process per enabled app, spawned at Oxine launch (or on install —
  installs are live, no relaunch). stdin/stdout = protocol, stderr = log file.

## Manifest

`manifest.json` at the repo root (read from the release's tag):

```json
{
  "id": "sha-dox.fngestures",
  "name": "FnGestures",
  "tagline": "Hold fn, gesture on the trackpad.",
  "icon": "hand.draw",
  "api": 1,
  "minOxine": "2.2.0",
  "run": { "arm64": "fngestures-arm64", "x86_64": "fngestures-x86_64" },
  "surfaces": {
    "settings": { "subtitle": "Gestures & actions" },
    "quickToggle": { "icon": "hand.draw", "tooltip": "FnGestures", "menu": true },
    "peek": true
  },
  "capabilities": ["notify", "storage"],
  "osPermissions": ["inputMonitoring", "accessibility"],
  "network": false
}
```

- `id` — reverse-ish slug, must match `creator.repo` (lowercased). Collisions
  are impossible by construction.
- `run` — release **asset names** per arch. `arm64` required, `x86_64`
  allowed but never required (macOS 26 still has Intel stragglers; Sous-style
  apps may skip it).
- `surfaces` — which extension points the app fills (see below). Static in the
  manifest so the store page can show them before install.
- `capabilities` — ring-1 host APIs the app may call/subscribe (grant sheet).
- `osPermissions` — ring-2 TCC permissions the app's own process will request.
  Declarative honesty for the grant sheet + our Permissions panel; macOS
  enforces the actual grants against *their* binary, not Oxine.
- `network` — declared for the grant sheet. NOTE: not technically enforceable
  on an unsandboxed process; it is a policy/curation signal, and we say so in
  the UI ("declares no network use") rather than pretending it's a sandbox.

## Distribution, install, trust

Resolution: `creator/repo` → GitHub API → latest release → `manifest.json`
asset (or repo file at the tag) → download the arch's binary asset.

- **Hash pinning**: the release carries `SHA256SUMS` (one line per asset,
  generated by CI); Oxine verifies before first run and on every update.
- **Provenance (badge, required for the featured shelf)**: GitHub artifact
  attestations (`actions/attest-build-provenance`). Oxine verifies the binary
  was built by that repo's CI from that tag — "this binary is the code you can
  read". One YAML line for creators; sigstore bundle verification on our side.
- **Signing**: none required. `swift build` ad-hoc signs on Apple Silicon; we
  download via URLSession without `LSFileQuarantineEnabled`, so Gatekeeper
  never assesses (standard plugin-ecosystem behavior). **Developer ID is
  recommended only for apps with `osPermissions`** — TCC keys grants to the
  signing identity, so ad-hoc apps re-prompt after every update. Store badge +
  post-update permission re-check (reuse the Settings → Permissions muscle).
- **Updates**: poll releases on the store's cadence; show changelog; hash and
  (if present) attestation re-verified; hot-swap the process.
- **Discovery**: the in-app store (see below) + `oxine-app` GitHub topic +
  `oxine://install/creator/repo` deep link for READMEs.

## Store (Settings → Apps)

Entry point is a single Settings row, styled like the others:

    [icon]  Apps
            Browse, install & manage           >

It pushes a store pane inside the existing Settings navigation (same glass,
same list language — it should feel like Settings grew a room, not like a
web shop got embedded):

- **Installed** — one row per app: icon · name · tagline, enable toggle,
  update badge; tapping opens the app's detail page (surfaces it offers,
  capability grants with revoke switches, OS-permission status, log viewer,
  uninstall with keep-data option).
- **Featured** — shelf from `oxineapp/registry` JSON. **Curated by us**:
  listing happens via PR to the registry repo, reviewed and merged only by
  the Oxine team (provenance badge + manifest sanity + a look at the source
  are the bar). Direct `creator/repo` installs need no approval from anyone.
- **Get more** — search by GitHub topic + a direct `creator/repo` field.
- Install flow: detail preview (tagline, surfaces, capabilities, permissions,
  badges) → grant sheet → live install, no relaunch. The new app's surfaces
  appear immediately; placement is then arranged where the user already
  arranges things (tab bar editor, footer slots, notch tab order).

## Surfaces

Each maps to an existing seam in the codebase:

| Surface | Declares | Runtime messages | Host seam |
|---|---|---|---|
| `panelTab` | icon, title | `view` trees | `Tabs.swift` — `TabID` enum becomes identity that admits `app:<id>` alongside built-ins (persistence is already raw strings; `"notes"` stays `"notes"`) |
| `settings` | subtitle | `view` trees (form vocabulary) | Settings list row is free from the manifest (icon · name · subtitle, like "Sous · Battery"); pane pushes like any built-in |
| `quickToggle` | icon, tooltip, menu | `toggle` state + menu items; tap + menu-pick events | `FooterView` (`MainView.swift`) — slots user-assignable in Settings. Primary click = the app's one-click action; right-click = its context menu. Caffeine/Focus are the archetypes |
| `notchTab` | icon, title | `view` trees | `NotchModule` — a `RemoteNotchModule` adapter fills id/title/icon/expandedView from the protocol |
| `barMetric` | label | `metric` values (0…1) | notch bar source list (Settings → Notch), next to CPU/GPU/fan/Claude |
| `peek` | — | `peek` requests (icon + text, transient) | `NotchController.peek(_:)` |
| `action` | name, input kind | invoke → result | today's plugin system, absorbed: a plugin is an app with only `action` surfaces |

v1 explicitly does **not** offer: custom drawing, drag-source/drop-target
surfaces, text-editor components. The vocabulary grows demand-driven;
ExtensionKit remote SwiftUI is the v2 escape hatch if someone truly needs a
canvas.

## View vocabulary (v1)

JSON tree; nodes have `type`, optional `id` (event ref), `props`, `children`.
Rendered with PanelKit styling; **components own their micro-interactions and
animations host-side** — apps send state changes, never frames.

Layout: `vstack` `hstack` `zstack` `grid` `spacer` `divider` `scroll`
Content: `text` (style: title/body/caption/mono) `icon` (SF Symbol) `image`
  (b64, downsampled by host) `card` (GlassCard) `emptyState`
Data: `meter` `gauge` `sparkline` `progress` `badge` `keyValueRow`
Controls: `button` `toggle` `slider` `stepper` `picker` `textField`
  `keyRecorder` `list` (+ `row`, swipe actions from a fixed verb set)
Form (settings): `section` with header/footer, rows of the above.

Example (a settings pane fragment):

```json
{"t":"view","surface":"settings","body":[
  {"type":"section","props":{"header":"Gestures"},"children":[
    {"type":"row","id":"g-vol","props":{"title":"fn + scroll","value":"Volume"},
     "children":[{"type":"picker","id":"g-vol-pick",
       "props":{"options":["Volume","Brightness","Off"],"selected":"Volume"}}]},
    {"type":"toggle","id":"swallow","props":{"title":"Swallow scroll events","on":true}}
  ]}
]}
```

Full-tree updates; the host diffs by `id`/position and animates transitions.

## Protocol

NDJSON, one message per line. App's stdout → host, stdin ← host. stderr goes
to `<id>/app.log` (viewable from the store page).

Handshake:
```
host → {"t":"hello","api":1,"oxine":"2.2.0","granted":["notify","storage"],"dataDir":"…"}
app  → {"t":"ready"}
```

App → host:
- `{"t":"view","surface":"panelTab","body":[…]}` — replace a surface's tree
- `{"t":"toggle","active":true,"icon":"moon.fill","menu":[{"id":"m15","title":"15 minutes"},{"id":"m60","title":"1 hour"},{"id":"off","title":"Turn off"}]}` — quickToggle state; `menu` (optional) is what right-click shows, kept current by the app
- `{"t":"metric","value":0.42}` — bar metric
- `{"t":"peek","icon":"speaker.wave.2","text":"40%"}` — transient notch peek.
  **Rate-limited by the host**: token bucket per app (burst 2, refill 1 per
  30s); excess requests are coalesced — newest replaces queued, never stacks.
  All peeks (apps + built-ins like track change) share one queue; nothing
  peeks while the notch is expanded. An app that hammers the limit gets the
  watchdog treatment (throttle → badge), same as message flooding. Peeks are
  for *state changes the user would want to notice*, not telemetry — the
  limiter makes that the only strategy that works.
- `{"t":"call","id":7,"fn":"notify.post","args":{…}}` — capability call
- `{"t":"sub","cap":"temper.metrics","hz":0.5}` / `{"t":"unsub","cap":…}`

Host → app:
- `{"t":"event","surface":"settings","ref":"swallow","kind":"change","value":false}`
- `{"t":"event","surface":"quickToggle","kind":"tap"}` — primary click
- `{"t":"event","surface":"quickToggle","kind":"menu","ref":"m15"}` — right-click pick
- `{"t":"cap","cap":"temper.metrics","data":{…}}` — subscription tick
- `{"t":"ret","id":7,"ok":true,"data":{…}}`
- `{"t":"lifecycle","phase":"activate","surface":"panelTab"}` — tab
  shown/hidden (apps should idle their updates when nothing is visible)
- `{"t":"bye"}` then SIGTERM (grace 2s) on disable/quit.

Versioning: `api` is the contract. Additive changes stay `1`; breaking bumps
to `2`, and the host runs older-api apps in compatibility as long as feasible.

## Capabilities (ring 1, v1)

Granted per-app at install (sheet), revocable in the store page.

- `storage` — KV store scoped to the app (plus `dataDir` is always available)
- `notify` — post user notifications (as "Oxine · <AppName>")
- `openURL` — open a URL/app (user-gesture-gated: only in response to a tap)
- `media.nowPlaying` — stream what NowPlayingManager sees
- `system.usage` — CPU/GPU/mem stream (`SystemUsage`)
- `sous.state` — battery telemetry + Sous mode (read; from `SMCReader`)
- `temper.metrics` — temps/fans stream (read; from `ThermalReader`)
- `clipboard.write` — put text on the clipboard
- `clipboard.read` — **high-trust**: separate scary grant, off by default,
  double-confirmed. (History access: not in v1 at all.)

Never exposed: Keychain/TOTP anything, notes content, raw SMC writes, the
privileged helpers. If a real use case needs a privileged verb (say
`sous.topUp`), it ships as a first-party audited capability, never raw access.

Ring 2 reminder: input taps, HID, multitouch etc. need no capability — the
app's own process asks macOS, and macOS prompts naming *their* binary. We just
declare it (`osPermissions`) and surface grant status.

## Lifecycle & supervision

- Spawn on enable/launch; `bye`+SIGTERM on disable; SIGKILL after grace.
- Crash: restart with backoff (1s/5s/30s); 3 crashes in 5 min → disabled +
  badge on the store page and the app's surfaces show an error state.
- Watchdog: sustained CPU abuse or message flooding (> N msg/s) → throttle,
  then suspend + badge. Same discipline as the 2.1.1 notch-bar cadence work:
  a misbehaving app degrades *itself*, never the panel or the notch.
- Uninstall: SIGTERM, delete `<id>/` (offer to keep `data/`), revoke grants.

## Security model (honest version)

The boundary protects **Oxine's** crown jewels: an app can never reach the
Keychain items, notes, or clipboard history behind Touch ID, and never rides
on Oxine's TCC grants. It does **not** make third-party binaries safe in
general — an unsandboxed process is arbitrary user-level code, same trust as
installing any Mac app. We say this plainly in the install sheet. Trust
signals, not theater: provenance badge (built-from-source proof), Dev ID
badge, curation for the featured shelf, capability + permission declarations
up front, and one-click full removal.

## SDK — `OxineKit`

Separate repo `oxineapp/OxineKit`, **MIT** (it never links the GPL app; the
protocol boundary keeps app licensing the creator's choice — though
install-from-GitHub means source is public anyway).

- Result-builder DSL that compiles to the view tree
  (`Section("Gestures") { Toggle("Swallow scroll", $swallow) }` — reads like
  SwiftUI, emits JSON)
- Typed capability clients, protocol pump, event routing to closures
- `@main OxineApp` entry point: creators implement `body(surface:)` + handlers
- Template repo (`oxineapp/app-template`): manifest, SDK dep, release workflow
  with `SHA256SUMS` + attestation preconfigured. `git clone` → working
  quickToggle app in ~30 lines.

## Dogfooding (validation before any third party)

Port **Caffeine** (`CaffeineManager.swift`) and **Focus**
(`FocusModeManager.swift`) to run as internal apps over the real protocol —
they're exactly the footer-toggle archetype the store replaces. If the
vocabulary + protocol can't express our own two simplest features cleanly,
fix it before publishing `api: 1`. (They can stay compiled-in — "internal
apps" — no need to actually spawn processes for them in release builds.)

## Build order

1. `AppsManager` (install/update/spawn/supervise) + protocol pump + grants
2. Renderer + vocabulary for `settings` + `quickToggle`; footer slots UI
3. Dogfood Caffeine/Focus; freeze `api: 1`
4. `panelTab` (+ `TabID` → identity refactor) and notch surfaces
   (`RemoteNotchModule`, bar metric, peek); absorb plugins as `action` apps
5. OxineKit + template repo + the Settings store pane (installed/featured/get-more, deep link)
6. Registry repo, provenance verification, launch

## Open questions

None — design is settled; changes from here go through this doc.

## Implementation status (2026-08-18)

Landed in `Sources/Oxine/Apps/` + integration points:

- **Protocol `api: 1`** — `AppProtocol.swift` (NDJSON messages both ways),
  `AppJSON.swift`, `AppViewTree.swift`. Frozen as speced above, plus:
  `toggle` carries an optional `text` caption (Caffeine's countdown) and its
  `menu` items support `checked`/`destructive`/`divider`.
- **Backends** — `AppBackend.swift`: `AppProcessBackend` (child process,
  line-buffered NDJSON, stderr→app.log, 200 msg/s flood kill, off-main stdin
  writes) and `InternalAppBackend` (in-process dogfood shim).
- **Supervision** — `AppRuntime.swift`: crash restarts at 1s/5s/30s, disabled
  after 3 crashes/5 min; peek token bucket (burst 2, 1/30s); capability subs
  with host-side Hz ceilings; openURL gated on a <10s-old user event.
- **Manager** — `AppsManager.swift`: scan/install/update/uninstall,
  `creator/repo` resolution via GitHub releases, SHA256SUMS verification
  (unverified badge when absent), grants + enabled + footer slots persistence,
  registry fetch, `oxine-app` topic search.
- **Renderer** — `AppViewRenderer.swift`: the full v1 vocabulary (layout,
  text/icon/image/card/emptyState, meter/gauge/sparkline/badge/keyValueRow,
  button/toggle/slider/stepper/picker/textField/keyRecorder, section/row/list).
- **Surfaces** — footer slots (`AppQuickToggleButton` in `FooterView`, user
  assignment UI in the store), settings rows + panes, panel tabs (`TabID` →
  `PanelTab` identity refactor; app tabs persist as `app:<id>` and filter
  when unresolvable), notch tabs (`RemoteNotchModule`), bar metrics
  (`ExternalBarMetric` in NotchKit + settings picker entries), peeks.
- **Store** — `AppsStoreView.swift` under Settings → Apps: installed list,
  footer-slot editor, featured shelf, community browse, `creator/repo` check →
  preview (surfaces, grant toggles, OS permissions, network line, trust copy)
  → live install.
- **Dogfood** — `InternalApps.swift`: Caffeine + Focus run over the real
  protocol (menu with checkmarks, countdown caption, destructive item —
  they exercised every quickToggle feature).
- **Validated end-to-end** — a local `oxineapp.demo` (python NDJSON app)
  spawns supervised, wires stdin/stdout/stderr, and exercises panel tab,
  settings, quickToggle+menu, notch tab, bar metric, peek, `system.usage`
  subscription, and `notify` calls.

Deferred (next):
- `media.nowPlaying` capability (needs a NotchKit snapshot hook; listed in the
  ring-1 spec, not yet brokered — unknown caps degrade gracefully).
- Provenance verification (sigstore attestation checking; hash pinning works).
- `action` surface + absorbing the existing Scripts/plugins system.
- `oxineapp/OxineKit` SDK repo + `oxineapp/app-template` + `oxineapp/registry`
  (external repos to create and publish).

## Update (2026-09-15) — bundled apps

- **Bundled kind** — `OxApp.Kind.bundled`: first-party apps that ship inside
  the binary but *install* from the store (Settings → Apps → "From Oxine").
  In-process like the dogfood apps (they need an overlay panel / an event tap),
  same protocol, removable; uninstall stops them and wipes their settings.
  Persisted as `appsBundledInstalled`. Catalog: `Apps/Bundled/BundledApps.swift`.
- **ScreenLyrics** (`oxine.screenlyrics`) — the lyric overlay lives in NotchKit
  (`Lyrics/ScreenLyrics.swift`, riding the notch's player feed); the app turns
  it on for its lifetime, draws the settings pane through the view tree, and
  offers a footer toggle (same switch as the song-page button). Compact glass
  pill by default; the large configurable box is the other style.
- **FnGestures** (`oxine.fngestures`) — one CGEvent tap (`FnGestureEngine`):
  fn + vertical scroll ramps volume/brightness, fn + horizontal flick skips
  tracks. Actions are ordinary system key events; needs Accessibility only.
- **Vocabulary (additive)** — `slider` gained `step` and `valueText`.
